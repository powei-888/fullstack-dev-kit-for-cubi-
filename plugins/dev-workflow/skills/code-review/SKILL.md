# Code Review 流程

預設唯讀：不切換分支、不修改檔案、不在遠端留言，除非使用者要求。專案自己的規範（`AGENTS.md`、專案 skill）是審查依據，優先於本檔的通用清單。

## 流程

1. **確定範圍**：PR 用唯讀方式取得描述與 diff；本機變更用 `git status`、`git diff`、`git diff --staged`。
2. **載入依據**：讀專案的 `AGENTS.md` 與和變更相關的專案 skill 或規範文件。
3. **逐項檢查**下方清單。
4. **輸出結果**：每個發現都要有檔案位置、問題、違反的專案規則（有的話）與修正方向。

## 檢查清單

- **安全與資料完整性（Critical）**：認證與授權是否在伺服器端檢查且預設拒絕；輸入是否參數化或白名單；輸出是否跳脫；有沒有寫死的機密；log 是否含敏感內容。
- **正確性（High）**：錯誤路徑、邊界值、並行與重試、狀態是否正確寫回、有沒有被吞掉的例外。
- **架構（High）**：是否符合專案的分層與模組邊界；有沒有繞過既有的共用服務自己實作一份。
- **資源（High）**：N+1 查詢、沒有分頁或上限的查詢、沒有上限的重試或批次。
- **測試**：新行為與失敗路徑是否有測試；測試是否驗證行為而不是實作細節。
- **可維護性（Normal）**：命名、重複、被取代的舊程式是否移除、註解是否說明「為什麼」。
- **文件**：行為或契約改變時，對應文件是否同批更新。

## 嚴重程度

| 等級 | 意義 | 處置 |
| --- | --- | --- |
| Critical | 安全漏洞、資料遺失或毀損風險 | 阻擋合併 |
| High | 功能錯誤、破壞架構邊界、明顯效能問題 | 合併前修復 |
| Normal | 可維護性、風格 | 修復或記錄為待辦 |

## 輸出格式

```markdown
## 審查範圍
## 發現
### [Critical|High|Normal] 標題 — `path/to/file:行號`
- 問題：
- 規則：（專案規則編號，沒有就省略）
- 建議：
## 已執行與未執行的驗證
## 結論：可合併 / 需修改
```

沒有發現時明確寫「未發現需要阻擋的問題」，並列出審查了哪些檔案。只回報有具體位置與理由的問題；純風格偏好標為可選。
