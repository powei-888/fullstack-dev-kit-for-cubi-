# 除錯流程

目標是找到根因並證明修好了，不是讓錯誤訊息消失。專案自己的規範（`AGENTS.md`、專案 skill）優先於本檔。

## 流程

1. **重現**：寫下預期行為、實際行為、重現步驟、最近的相關變更。無法重現時說明試過什麼，不要憑猜測改程式。
2. **蒐證**：錯誤訊息、stack trace、request id／trace id、相關 log、觸發的輸入資料。不要把密碼、token 或使用者資料貼進回報。
3. **列假設**：依可能性排序，一次只驗證一個。常見方向：邏輯錯誤、資料異常、非同步順序、設定或環境、相依套件或服務。
4. **縮小範圍**：最小重現、二分法、`git bisect`、在關鍵點加暫時 log。暫時 log 修完後移除。
5. **確認根因**：說明機制，也就是為什麼會發生、為什麼先前沒有被測試擋下。只能解釋部分現象的假設不算根因。
6. **修復**：只改根因所在的地方，維持最小範圍。發現需要重構時先完成最小修正，再另外提出。
7. **驗證**：補一個修復前失敗、修復後通過的測試，再跑相關測試確認沒有退化。做不到時說明原因與替代驗證。

## 判斷真相來源

狀態類問題先查持久化的正本（通常是資料庫），再查 queue、cache、索引、前端 store。後者是衍生狀態，可能過期。

## 常見模式

- 差一：迴圈邊界、分頁、區間開閉。
- 空值：未檢查的 `null`／`undefined`、API 回應缺欄位。
- 非同步：完成順序與預期不同、共用狀態沒有保護、漏掉 `await`。
- 過期狀態：cache 沒更新、閉包抓到舊值。
- 型別：字串與數字比較、隱性轉型。

## 回報格式

問題描述、根因、修改內容、已執行的驗證與結果、未驗證的部分、預防方式。
