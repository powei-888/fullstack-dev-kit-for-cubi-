# 完成前自我審查

這是 agent 自己的最後一道檢查，不取代 PR review 與 CI。專案自己的規範（`AGENTS.md`、專案 skill）優先於本檔。

## 步驟

1. 看完整差異：`git status --short`、`git diff`，已 stage 的用 `git diff --staged`。只審查這次的異動。
2. 逐項檢查，每項都要有結論：
   - **範圍**：差異有沒有超出需求？有沒有動到專案規定要先提方案才能改的東西？
   - **專案規則**：有沒有違反專案 `AGENTS.md` 或專案 skill 中與本次異動相關的條文？
   - **安全**：查詢是否參數化、輸出是否跳脫或消毒、有沒有寫死的金鑰或密碼、log 有沒有敏感內容。
   - **殘留**：`debugger`、暫時的 `console.log`／`print`、被取代卻沒刪的舊程式、過期註解。
   - **契約**：API、資料庫 schema、對外事件格式有沒有被改動？有的話文件與測試是否同批更新？
3. 發現問題先修再回報。修不了或超出範圍的，列為待辦並說明風險。
4. 執行專案規定的檢查（型別檢查、lint、相關測試）。

## 回報

分開寫三類，不可混在一起：

- 已執行的驗證指令與結果。
- 沒有執行的驗證與原因。
- 審查中發現但沒有處理的問題。

沒有驗證過的行為不可寫成「已確認」。
